## 4. 关键设计决策（按时序）

### 4.1 相对 HyperFrames 的 plugin 壳

- 镜像 HF：`.codex-plugin` + `skills/` + brand assets + git-archive 打包。
- 主 skill 来自桌面 `vidmuse-recut` 0.1.0，并 vendor HF core + GSAP。

### 4.2 路由冲突与改造

**问题：** vendored `hyperframes/SKILL.md` 原是 “Mandatory entry”，会抢「包装口播」并指向未装载的 `/talking-head-recut`。

**改法：**

- `hyperframes` description 去 packaging 触发词；§0 强制 handoff → `/vidmuse-recut`。
- THR route → redirect stub；capability-menu overlay 行改 recut。
- `vidmuse-recut` 自封 sole product router。
- `references/` 加 inventory banner；`skill-lifecycle` 改为 plugin override。

### 4.3 Timeline：多轨，不是做成片播放器

**问题：** Step 13 曾写死 main 只挂 `output.mp4`，「timeline never gates effects」。

**用户纠正：** `vidmuse serve` = DSL 多轨预览（原片 + 包装点 + 字幕），与 HF **不冲突**（层 vs 时间线）。

**改法：**

- `references/vidmuse-timeline.md`
- `scripts/write_dsl.py`（`--mode layered|baked`，`--no-overlay`）
- `templates/dsl.layered.example.json`
- SKILL Step 2 起可 early serve；Step 10/13 默认 layered；baked 仅 fallback。

分辖：

```text
HyperFrames  = 包装层怎么动、合不合合同
vidmuse serve = 原片 + overlay + subtitles 怎么排在时间线上给人看
```

### 4.4 健康检查：全局 CLI vs plugin skills

**用户问：** 检测的是全局 skill 还是插件内？CLI 要全局，skill 用 plugin 即可。

**改法（setup.sh 0.2.4）：**

| 全局 PATH 必须有 | 仅认 `<plugin>/skills/*` |
| --- | --- |
| node 22+, ffmpeg, python3 | vidmuse-recut + HF* + media-use + gsap* |
| `vidmuse`（serve/render/model）+ login | **不**扫描 `~/.codex/skills` |
| `npx hyperframes doctor` | 缺 skill → 失败要求重装 plugin |

已删：mirror 到 `~/.codex/skills`；缺 skill 时 `npx hyperframes skills update` 裸装 fallback。

Vendor CLI：PATH 无 `vidmuse` 时从 plugin 拷到 `/usr/local/bin` 或 `~/.local/bin`。

### 4.5 工作目录

- **Skill/plugin 目录只读。**
- 产物在**会话工作区**：`videos/<project>/`（HF 习惯），或用户指定目录。
- **不要**在 `vidmuse-codex-plugin/` 里出片。
- 测试实例正确落在：  
  `…/new-chat/videos/ai-native-first-2min`。

## 7. 品味问题（用户不满意）——核心结论

用户反馈：**出来效果审美/品味不符合预期。**

### 7.1 不是什么

- **不是** THR/路由抢活（测试时主路由正确）。
- **不是** `hyperframes-creative` 与 recut「架构宣战」；creative 文档写设计 spec 优先、house-style 补缺。

### 7.2 是什么

更像：

1. **品味源过多**：recut taste + creative house-style/typography/video-composition + 多 pack 比较，无「一锤定音」的压制顺序。  
2. **Director「句句要证明」** × **两分钟单机位无 B-roll 无真数据** → 被迫上流程轨/时间轴/扩散网/压力环/模块栈。  
3. **锚点漂移**：名义 `editorial-intelligence`，实践「半轨 technical-blueprint」。  
4. **默认中文字皮**：PingFang 特黑 + IBM Plex Mono 状态语（EXPIRED/STALE/ACTIVE）→ SaaS/方法论片感。  
5. **观感阶段**：主要是 showcase 静帧，工程图完整时更「设计作业」。

### 7.3 FRAME 自称的方向（便于改）

- paper `#F2E8D8` / ink 墨绿 / teal / signal 橙  
- 签名：一条变形「变化轨道」跨多 act  
- 拒绝：蓝紫 AI 渐变、句句成卡、假数据假 X 帖  

### 7.4 已议纠偏方向（未落地改 skill/片）

**规则层（改插件）：**

```text
审美权威序：
1 用户 BRIEF / 源片气质
2 packaging 密度（静段）
3 项目 FRAME.md（唯一 token 法源）
4 recut atoms/profiles（至多一锚点）
5 hyperframes-creative 仅卫生/反网页
6 Registry 机制不带皮肤
```

- 方向阶段 **不要** 把 creative 当完整选型菜单；FRAME 立后抽查即可。  
- 纯静口播默认更 Packaging，非明确 launch 不重 Director 证明。  
- FRAME 自检加：source-led 占比、状态文言数量、是否双锚。

**片子层（磨 FRAME + showcase，可不重跑对齐）：**

1. 砍一半系统戏：1 Hero 全屏证明 + 1–2 轻轨，多 source-only。  
2. 锚点二选一：稳暖编辑 **或** 诚实 blueprint，禁止各借一半。  
3. 少 chip 状态词，多中文判断句。  
4. 减 Plex Mono 霸权；跟墙/衣服取色，少全屏 night 蓝图。  
5. showcase 先问「像不像这间屋」，再问「论证清不清」。
